vigil mobile
tech spec

Implementation plan for vigil-server — a new Rust crate that exposes vigil's session registry over HTTP + WebSocket, enabling a mobile PWA to monitor and respond to agent sessions from anywhere via Tailscale.

01 What We're Building

Three new pieces, each landing separately:

  1. 1
    vigil-server crate — axum HTTP server that wraps the existing adapter pipeline and session registry. Runs as a subcommand: vigil serve.
  2. 2
    PWA client — static HTML/CSS/JS served directly from vigil-server. No separate build step. Install to home screen on iOS/Android.
  3. 3
    Tailscale connectivity — vigil serve --tailscale binds to the Tailscale interface IP, making the server reachable from any device on your tailnet, including your phone on LTE.

The TUI (vigil) and the server (vigil serve) are independent processes reading the same files. Neither blocks the other. You can run both simultaneously.

Key constraint

vigil-server must be read-only by default on the file system — same invariant as the TUI. The only write operations are: spawning agent processes for send_message / respond, and writing the VAPID key + push subscription files to ~/.vigil/.

  your laptop                                   your phone (LTE / Wi-Fi)
  ──────────────────────────────────            ──────────────────────────
  ~/.claude/projects/*.jsonl                    vigil PWA (home screen)
  ~/.pi/agent/sessions/*.jsonl                      │

  │  │ probe loop   │──┼──►│ broadcast::Sender │──► WebSocket clients
  │  │ (tokio task) │  │   └──────────────────┘
  │  └──────┬───────┘  │
  │         │probe()   │   ┌──────────────────┐
  │  ┌──────▼───────┐  │   │ axum Router      │
  │  │  AdapterMap  │  │   │  GET /api/sess.. │
  │  │  (Arc, Sync) │  │   │  WS  /events     │
  │  └──────────────┘  │   │  POST /api/sess..|
  │                    │   │       /respond   │
  │  (same adapters    │   └──────────────────┘
  │   as vigil TUI)    │
  └────────────────────┘

The probe loop runs every 2 seconds (vs TUI's 1s — less aggressive since mobile doesn't need instant feedback). It calls each adapter's probe() in parallel, diffs the result against the previous snapshot, and broadcasts change events on a tokio::sync::broadcast channel. WebSocket connections subscribe to that channel.

04 Shared State

AppState

use std::sync::Arc;
use tokio::sync::{broadcast, RwLock};
use vigil_core::{AgentAdapter, AgentKind, Container};

#[derive(Clone)]
pub struct AppState {
    pub adapters: Arc<HashMap<AgentKind, Arc<dyn AgentAdapter>>>,
    pub snapshot: Arc<RwLock<Vec<Container>>>,  // latest probe results
    pub tx: broadcast::Sender<EventDto>,         // fan-out to WS clients
    pub token: Arc<String>,                       // bearer token for auth
    pub start_time: std::time::Instant,
}

impl AppState {
    pub fn new(adapters: HashMap<AgentKind, Arc<dyn AgentAdapter>>, token: String) -> Self {
        let (tx, _) = broadcast::channel(256);
        Self {
            adapters: Arc::new(adapters),
            snapshot: Arc::new(RwLock::new(vec![])),
            tx,
            token: Arc::new(token),
            start_time: std::time::Instant::now(),
        }
    }
}

DTOs (wire types)

We define separate DTO types rather than serializing Container directly — this decouples the API from internal type churn.

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ContainerDto {
    pub id: String,
    pub repo: String,                // repo_root.file_name() for display
    pub branch: String,
    pub agent: String,               // "claude" | "pi"
    pub state: String,               // "AwaitingInput" | "Running" | "Idle" | "Done" | "Error"
    pub state_reason: Option<String>, // e.g. permission prompt text
    pub last_message: Option<String>, // truncated to 120 chars
    pub last_activity: Option<String>, // ISO 8601
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct LogDto {
    pub events: Vec<LogEventDto>,   // structured turns
    pub lines: Vec<String>,          // raw fallback lines
    pub total_turns: usize,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum EventDto {
    Snapshot   { containers: Vec<ContainerDto> },
    Updated    { container: ContainerDto },
    Removed    { id: String },
}

05 Probe Loop

pub async fn run_probe_loop(state: AppState) {
    let mut interval = tokio::time::interval(Duration::from_secs(2));
    interval.set_missed_tick_behavior(MissedTickBehavior::Skip);

    loop {
        interval.tick().await;

        let registry = Registry::load().unwrap_or_default();
        let entries = registry.entries().to_vec();

        // Probe all entries in parallel
        let results: Vec<_> = entries.iter().map(|e| {
            let adapters = state.adapters.clone();
            let entry = e.clone();
            tokio::spawn(async move {
                let adapter = adapters.get(&entry.agent)?;
                let result = adapter.probe(&entry.worktree_path).await;
                Some((entry, result))
            })
        }).collect();

        let containers = join_all(results).await
            .into_iter()
            .flatten()
            .flatten()
            .map(|(entry, probe)| container_from_probe(entry, probe))
            .collect::<Vec<_>>();

        // Diff against snapshot, broadcast only what changed
        let mut snap = state.snapshot.write().await;
        diff_and_broadcast(&snap, &containers, &state.tx);
        *snap = containers;
    }
}
Important

The probe loop reads from Registry::load() on every tick — this picks up new worktrees added by atelier wt new while the server is running, with a 2-second lag. No need to watch the registry file separately.

07 WebSocket Events

WS /events
Client connects. Server immediately sends a snapshot event, then streams updated or removed events as state changes. 
// On connect: full snapshot
{ "type": "snapshot", "containers": [...] }

// When a container's state changes
{ "type": "updated", "container": { "id": "vast-babbage", "state": "AwaitingInput", ... } }

// When a worktree is removed from registry
{ "type": "removed", "id": "vast-babbage" }

PWA WebSocket client sketch

function connectEvents(onUpdate) {
  const ws = new WebSocket(`wss://${HOST}/events`);

  ws.onmessage = (e) => {
    const ev = JSON.parse(e.data);
    if (ev.type === 'snapshot')  store.set(ev.containers);
    if (ev.type === 'updated')   store.upsert(ev.container);
    if (ev.type === 'removed')   store.remove(ev.id);
    onUpdate();
  };

  ws.onclose = () => setTimeout(() => connectEvents(onUpdate), 3000);
  return ws;
}

The PWA reconnects automatically on close. When the phone's network changes (e.g. Wi-Fi → LTE → Tailscale reconnects), the client re-establishes within 3 seconds.

08 Respond & Send Message

POST /api/sessions/:id/respond
Approve or deny the current permission prompt. Body: {"action": "approve"} or {"action": "deny"}. Maps to adapter.send_message(dir, session_id, "y\n") or "n\n". Returns 204 No Content on success.

Adapter mapping:
Agentapprovedeny
claudesend_message("y\n")send_message("n\n")
pisend_message("yes\n")send_message("no\n")
Each adapter's send_message already exists and fires --print mode. No changes to the adapters needed.
POST /api/sessions/:id/message
Send a freeform message. Body: {"text": "actually try the simpler approach first"}. Calls adapter.send_message(dir, session_id, text). Returns 204.
Session ID lookup

Routes use the registry container ID (branch name, e.g. vast-babbage) as the URL param, not the agent session ID. The route handler looks up the container from the snapshot, retrieves its session_id, and passes it to the adapter. Return 404 if not found, 409 if session_id is None.

09 Tailscale

No special Tailscale SDK required. Tailscale works at the network layer: once installed and running on your Mac, it creates a virtual network interface (utun) with a stable IP address (e.g. 100.x.y.z). Vigil-server just needs to bind to that interface.

How --tailscale works

  1. 1
    At startup, if --tailscale is set, run tailscale ip --4 via std::process::Command to get the machine's Tailscale IPv4.
  2. 2
    Bind axum's listener to {tailscale_ip}:{port} instead of 0.0.0.0:{port}.
  3. 3
    Print the Tailscale URL (http://my-machine.tailnet.ts.net:7777) to stdout and render it as a QR code in the terminal.
async fn resolve_bind_addr(opts: &ServeOpts) -> SocketAddr {
    if opts.tailscale {
        let out = Command::new("tailscale")
            .args(["ip", "--4"])
            .output().await
            .expect("tailscale not found — is it installed and running?");
        let ip: Ipv4Addr = String::from_utf8_lossy(&out.stdout)
            .trim().parse()
            .expect("could not parse tailscale IP");
        SocketAddr::from((ip, opts.port))
    } else {
        SocketAddr::from(([127, 0, 0, 1], opts.port))  // localhost only by default
    }
}
Security note

Without --tailscale, vigil-server binds to 127.0.0.1 only (localhost). You must explicitly opt in to network exposure. The bearer token (see §10) ensures even on Tailscale, only devices with the token can talk to the server.

Hostname (nice-to-have)

Tailscale assigns stable DNS names like my-macbook.tail12345.ts.net. Run tailscale status --json to get the local device's DNS name and display it alongside the IP in the startup banner. This is the URL the user will bookmark on their phone.

10 Auth & Security

Simple bearer token. Generated once at first startup, stored in ~/.vigil/server-token, printed in the terminal and encoded in the QR code.

fn load_or_create_token() -> String {
    let path = vigil_dir().join("server-token");
    if path.exists() {
        fs::read_to_string(&path).unwrap().trim().to_string()
    } else {
        let token = uuid::Uuid::new_v4().to_string();  // 36-char UUID
        fs::write(&path, &token).unwrap();
        token
    }
}

axum middleware

async fn require_token(
    State(state): State<AppState>,
    req: Request,
    next: Next,
) -> Response {
    let auth = req.headers()
        .get("Authorization")
        .and_then(|v| v.to_str().ok())
        .and_then(|s| s.strip_prefix("Bearer "));

    match auth {
        Some(t) if t == state.token.as_str() => next.run(req).await,
        _ => StatusCode::UNAUTHORIZED.into_response(),
    }
}

All routes under /api/ require the token. The /events WebSocket also requires it (sent as a query param: ?token=... since browsers can't set headers on WebSocket upgrades). The static PWA files (/, /app.js, etc.) are served without auth.

12 PWA Architecture

The PWA is a handful of static files embedded in the vigil-server binary using rust-embed. No build step, no npm, no bundler. Total target: <50KB of JS, unminified.

App.js architecture (vanilla JS)

// Three modules, no framework:

// 1. Store — source of truth (Map of id → container)
const store = {
  containers: new Map(),
  listeners: [],
  set(list)   { list.forEach(c => this.containers.set(c.id, c)); this.emit(); },
  upsert(c)   { this.containers.set(c.id, c); this.emit(); },
  remove(id)  { this.containers.delete(id); this.emit(); },
  emit()      { this.listeners.forEach(fn => fn()); },
};

// 2. Router — which view to show
const router = {
  view: 'list',        // 'list' | 'log' | 'settings'
  selectedId: null,
  navigate(view, id) { this.view = view; this.selectedId = id; render(); },
};

// 3. Render — pure function, called by store.emit()
function render() {
  document.getElementById('app').innerHTML =
    router.view === 'list'     ? renderList()  :
    router.view === 'log'      ? renderLog()   :
    router.view === 'settings' ? renderSettings() : '';
}

13 Push Notifications

Web Push (VAPID)

Web Push doesn't require a third-party relay. The browser has a built-in push service (FCM for Chrome/Android, APNs-backed Web Push for iOS 16.4+). vigil-server sends pushes directly to the browser's push endpoint using the VAPID protocol.

  1. 1
    VAPID key generation — on first startup, generate an EC P-256 key pair. Save as ~/.vigil/vapid-private.pem + ~/.vigil/vapid-public.b64. Serve the public key at GET /api/push/vapid-public-key.
  2. 2
    Subscription registration — PWA calls pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: vapidPublicKey }). Sends the resulting PushSubscription JSON to POST /api/push/subscribe. Server saves to ~/.vigil/push-subscriptions.json.
  3. 3
    Sending pushes — in the probe loop's diff_and_broadcast(), when a container transitions to AwaitingInput, Done, or Error, call push::send_notification(subscriptions, payload). Uses the web-push crate or raw VAPID signing.

self.addEventListener('push', e => {
  const data = e.data.json();
  e.waitUntil(

      body:    data.body,
      data:    data.data,

self.addEventListener('notificationclick', e => {
  e.notification.close();
  const { action, notification } = e;
  const { container_id } = notification.data;
  const base = `${self.location.origin}`;

  if (action === 'approve' || action === 'deny') {
    // Fire-and-forget from service worker
    fetch(`${base}/api/sessions/${container_id}/respond`, {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${TOKEN}`, 'Content-Type': 'application/json' },
      body: JSON.stringify({ action }),
    });
  } else {
    clients.openWindow(`${base}/sessions/${container_id}`);
  }
});
Token in service worker

The bearer token needs to be available in the service worker for approve/deny actions that fire without the app open. Store it in the service worker's self.token via a message event from the PWA during registration, and in IndexedDB for persistence across SW restarts.

15 CLI Integration

vigil-cli/src/main.rs grows a serve subcommand. The adapter instantiation is shared between both commands.

#[derive(Subcommand)]
enum Cmd {
    /// Monitor agent sessions in the terminal (default)
    Tui,
    /// Serve the vigil HTTP API + mobile PWA
    Serve {
        #[arg(long, default_value = "7777")]
        port: u16,
        /// Bind to Tailscale interface (accessible over tailnet)
        #[arg(long)]
        tailscale: bool,
    },
}

#[tokio::main]
async fn main() -> Result<()> {
    let cli = Cli::parse();
    let adapters = build_adapters()?;   // shared setup

    match cli.cmd.unwrap_or(Cmd::Tui) {
        Cmd::Tui         => vigil_tui::run(adapters).await,
        Cmd::Serve { port, tailscale } =>
            vigil_server::serve(ServeOpts { port, tailscale }, adapters).await,
    }
}

The default command remains vigil → TUI. The server is vigil serve. Both can run simultaneously from separate terminals.

# Today

> A warm, paper-like todo list that carries yesterday's unfinished work into
> today — an Elm frontend in a Tauri desktop shell.

Today is a minimalist daily todo app. Tasks you don't finish roll forward to the
current day automatically and surface in a labeled **Carried over** section with
a day-age tag (`3d`, `1d`) so you can see exactly what slipped. A calendar view
shows your completion history at a glance.

It's an Elm re-implementation of a [Claude Design](https://claude.ai/design)
prototype (`Today.html`), grounded in the Amigo design system: warm paper
surface, Flecha serif date, Diatype Mono eyebrows, and a clay accent used
sparingly on the checks, progress ring, and calendar dots.

## Features

- **Carry-over** — open tasks from previous days roll into today on load.
  Completed tasks stay anchored to the day they were finished, so history stays
  truthful.
- **Today list** — Carried over / Today / Completed groups, a progress ring,
  inline-editable titles, expandable notes (one sub-step per line), hover-only
  drag handles for prioritizing open tasks, and an add-task row.
- **Calendar history** — a month grid with a completion dot per finished task
  (open days show a hollow dot); pick any day to read what got done.
- **Local persistence** — your tasks are saved to **IndexedDB** (in the webview's
  own store). First run opens to an empty list, ready for your first task.

## Run it

The frontend is Elm; the desktop window is [Tauri](https://tauri.app). You need:

- [Elm 0.19.1](https://guide.elm-lang.org/install/elm.html)
- A Rust toolchain (`rustup`) and the Tauri CLI:
  `cargo install tauri-cli --version "^2.0"`

Then, from this `todo/` directory, use the Makefile:

```sh
make install    # build a release .app and copy it into /Applications
make launch     # open the installed app (installs it first if needed)
make run        # quick: build + run the debug binary directly (no install)
make dev        # Tauri dev mode (rebuilds the frontend on launch)
make help       # list all targets
```

`make install` installs the Tauri CLI on first use if it's missing. Under the
hood the build runs `./build.sh` to compile `src/Main.elm → web/elm.js`, then
bundles the `web/` frontend into a native app. You can also call the CLI
directly: `cargo tauri dev` / `cargo tauri build`.

### Frontend in a browser (no Tauri)

The frontend is plain static files, so you can also run it in a browser:

```sh
./build.sh --serve
# → http://localhost:8753
```

> **Why a server, not `file://`?** `index.html` loads `db.js` as an ES module
> and uses IndexedDB — browsers block both on `file://` origins.

## How it's built

```
todo/
├── build.sh                compile (src/Main.elm -> web/elm.js); --serve to preview
├── elm.json                Elm package manifest
├── src/                    Elm source (the frontend)
│   ├── Main.elm            the app: model, update, list + calendar views, ports
│   └── DateUtil.elm        dependency-free ISO-date math (civil-calendar algos)
├── web/                    static frontend Tauri bundles (frontendDist)
│   ├── index.html          page shell — links CSS/fonts, boots Elm, wires ports
│   ├── elm.js              compiled output (generated by build.sh; gitignored)
│   ├── db.js               IndexedDB <-> Elm port bridge
│   ├── styles/
│   │   ├── colors_and_type.css  Amigo design tokens + @font-face (from the design)
│   │   └── app.css              layout + components (from the prototype's <style>)
│   └── fonts/              Flecha S + ABC Diatype Mono web fonts
└── src-tauri/              the desktop shell (thin: just opens a window)
    ├── Cargo.toml          standalone crate (no top-level workspace)
    ├── tauri.conf.json     window config; frontendDist = ../web; build = ./build.sh
    ├── capabilities/       webview permissions
    ├── icons/
    └── src/{main,lib}.rs
```

**State lives in Elm.** The model holds the full task list; every mutation sends
the whole list to JavaScript through the `dbSave` port, and `db.js` writes it to
a single IndexedDB key. On startup Elm asks for the stored list via `dbLoad`,
receives it on `dbLoaded`, starting empty if nothing is stored, then applies
carry-over. "Today" comes from JavaScript as a flag, so the Elm side never needs
the wall clock.

**The shell is thin.** `src-tauri` has no custom commands — Rust just opens the
window and serves the bundled `web/` frontend. Persistence is entirely the
webview's IndexedDB, so the exact same code runs in a browser or on the desktop.

**Dates without dependencies.** `DateUtil` treats dates as `"YYYY-MM-DD"` strings
and converts to/from a day count using Howard Hinnant's civil-calendar
algorithms — enough for weekday, month length, add-days, and day-difference math
with no external time package.

## Notes on the design port

The original prototype shipped a "Tweaks" panel for exploring look directions
(Paper / Pure / Editorial, accent colors, density). Those were design-exploration
controls; this implementation bakes in the direction the design landed on — Paper
surface, Clay accent, serif weekday, regular density — and omits the panel.
Sub-tasks are free-text note lines rather than individually checkable items,
matching the prototype.
